Key Structural Difference — Where Assignments Live
FlexiPage Assignments
Inside CustomApplication (.app-meta.xml) under <profileActionOverrides> or <actionOverrides>, or inside CustomObject (.object-meta.xml).
Page Layout Assignments
Directly inside Profile (.profile-meta.xml) under the <layoutAssignments> block. Profile is always the source of truth.
Profile is always mandatory for page layout assignments — the assignment lives inside the Profile XML, not the layout file.

CLI Commit Guide

When you already know which XML block to add or remove, you can edit the file directly and commit from CLI — no Copado UI commit needed. This section covers every scenario: what component to commit, what block to touch, and when the FlexiPage is optional.

Key rule: The FlexiPage file is only required in your deployment if it doesn't already exist in the target org. If it's already deployed there, you can commit only the component that holds the assignment (CustomApplication or CustomObject or Profile) and the deployment succeeds.
SCENARIO 1 App Default — FlexiPage Assignment (Add or Remove)
Assignment lives in LTM_Sales_App.app-meta.xml → <actionOverrides>
Add Assignment via CLI
Component to commit: LTM_Sales_App (CustomApplication) only.

FlexiPage needed? Only if Account_Record_Page doesn't exist in the target org yet. If it's already there — skip it.

What to do: Open LTM_Sales_App.app-meta.xml, add the block below, then commit via CLI.
Condition: FlexiPage already in target org → commit CustomApplication only. FlexiPage not in target → commit both.
<!-- ADD inside .app-meta.xml -->
<actionOverrides>
  <actionName>View</actionName>
  <content>Account_Record_Page</content>
  <formFactor>Large</formFactor>
  <pageOrSobjectType>Account</pageOrSobjectType>
  <type>Flexipage</type>
</actionOverrides>
Remove Assignment via CLI
Component to commit: LTM_Sales_App (CustomApplication) only.

FlexiPage needed? No — removal just deletes the <actionOverrides> block from the app XML. The FlexiPage itself stays in the org untouched.

What to do: Open LTM_Sales_App.app-meta.xml, delete the entire block below, then commit via CLI.
Condition: Always safe to commit CustomApplication alone for removal. FlexiPage is never needed.
<!-- DELETE this block from .app-meta.xml -->
<actionOverrides>
  <actionName>View</actionName>
  <content>Account_Record_Page</content>
  <formFactor>Large</formFactor>
  <pageOrSobjectType>Account</pageOrSobjectType>
  <type>Flexipage</type>
</actionOverrides>

Assignment lives in Sales_User.profile-meta.xml → <layoutAssignments>
Add Assignment via CLI
Component to commit: Sales_User (Profile) only.

Layout file needed? Only if the layout is new or modified. If it already exists in target org — skip it. 
<!-- ADD inside Sales_User.profile-meta.xml -->

<!-- Without Record Type -->
<layoutAssignments>
  <layout>Account-Account (Sales) Layout</layout>
</layoutAssignments>

<!-- With Record Type -->
<layoutAssignments>
  <layout>Account-Account (Sales) Layout</layout>
  <recordType>Account.Enterprise</recordType>
</layoutAssignments>
Remove / Change Assignment via CLI
Component to commit: Sales_User (Profile) only.

Layout file needed? No — just update the <layoutAssignments> block in the Profile to point to the new layout (or delete the block entirely to remove). 
<!-- DELETE or REPLACE in Sales_User.profile-meta.xml -->
<layoutAssignments>
  <layout>Account-Account Old Layout</layout>
  <recordType>Account.Enterprise</recordType>
</layoutAssignments>

<!-- Replace with new layout -->
<layoutAssignments>
  <layout>Account-Account (Sales) Layout</layout>
  <recordType>Account.Enterprise</recordType>
</layoutAssignments>
